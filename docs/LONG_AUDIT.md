# 長時間検査とトークンの節約

反復検査はNode.jsとWindowsタスクスケジューラで実行し、AIを呼び出さない。AIは異常の調査・修正・最終確認に使う。トークン残量や会話の圧縮だけではOSプロセスの継続を保証できない。

## 開始と確認

プロジェクト直下のPowerShellから実行する。

```powershell
./scripts/start-audit-session.ps1 -Minutes 300
Get-ScheduledTask -TaskName 'MARS-*'
Get-Content tmp/<表示されたRunName>/status.json
```

5時間の期限は最初の起動時に固定する。タスクは1分間隔で起動を試み、実行中は重複起動しない。プロセスが消えた場合は完了済みゲームの続きから再開する。実行中だった1ゲームだけ再試行する。完了・検査失敗・コード変更・手動停止の後は再実行しない。CPUの3難易度、7盤面、1～5人、拡張あり／なしを順に検査する。複数人では通常・初期ドラフトを有効にする。

各手順で保存再読込、資源と生産下限、進行停止、最終得点を検査する。1ゲームの上限は2分。異常時はseedと理由、取得できた場合はゲーム状態を保存する。検査プログラムはコードの自動修正をしない。

`status.json` を完了件数・次のゲーム・期限の正本とする。書込み中は一時ファイルを使って置換する。`results.jsonl` は詳細記録であり、チェックポイント直後の強制終了では最後の1行が欠けることがある。成功件数をログの行数で上書きしない。

期限に到達したら処理中のゲームを終了し、未完走分は成功件数に含めない。`activeGameMs` は完走ゲームの処理時間で、休止時間や中断したゲームの時間を含まない。生成した検査ログとブラウザー検査の出力はLint対象から外す。

停止する場合は実行ディレクトリに `STOP` ファイルを作る。現在の1ゲームが終了すると停止する。直ちに止める場合は先にタスクを無効化してから停止する。

```powershell
New-Item tmp/<RunName>/STOP -ItemType File
Disable-ScheduledTask -TaskName 'MARS-<RunName>'
Stop-ScheduledTask -TaskName 'MARS-<RunName>'
```

この設定はログイン中のユーザーで動作する。PCの電源断・スリープ・ログアウト中の連続稼働は保証しない。復帰しても元の期限を延長しない。期限を過ぎれば残りを実行せず終了する。電源設定やモデル・料金設定は変更しない。

## 会話に戻す情報

- 通常は `status.json` の状態、件数、期限だけ読む。全ログを会話へ貼らない。
- 異常が出たときだけ、そのseedのログと該当コードを読む。
- 完了済みの監査を変更のたびに繰り返さない。変更に関係する回帰検査を行い、全体検査は区切りで実施する。
- 再開時はこの手順、最新の `status.json`、未解決の異常を先に読む。調査済みの経緯は再探索しない。

会話の圧縮は必要な状態を少ないトークンで引き継ぐ仕組みだが、この会話からAPIの圧縮設定を変更したわけではない。[OpenAI公式の説明](https://developers.openai.com/api/docs/guides/compaction)。
